# fix: resources bulk-action buttons and Manage all views are non-functional

## Problem statement

Three Resources-page interactions are non-functional in mock mode:

1. **Bulk action bar — Apply tag…** (`ResourcesPage.jsx:598`): clicking does nothing. The matching control on `/tag-governance` (`TagGovernancePage.jsx:249`) opens the existing `ApplyTagModal` component — the Resources page should do the same with `resourceIds` set to the current selection.
2. **Bulk action bar — Hibernate, Send to Recommendations, Export selected** (`ResourcesPage.jsx:599-601`): also no `onClick` handlers. Each currently silent.
3. **View dropdown — Manage all views…** (`ResourcesPage.jsx:177`): no `onClick`.

## Scope

In scope:
- Apply tag…: open `ApplyTagModal` with the selected resource IDs. Already exists at `frontend/src/components/ApplyTagModal.jsx` with signature `{ resourceIds, onClose, onApplied }`.
- Hibernate: show a confirmation toast/inline feedback ("N resources queued for hibernation") and clear the selection. No real action needed in mock.
- Send to Recommendations: navigate to `/recommendations` (the existing optimize page).
- Export selected: download a CSV of the selected rows only (use the existing `buildResourcesCsv` helper).
- Manage all views…: open a simple modal listing the saved views with delete/rename affordance. Minimal acceptable: a placeholder dialog with the saved-view names listed and a Close button.

Out of scope:
- Real backend mutation for Hibernate or tag-write.
- Designing a polished views-management UI; a basic listing is acceptable.

## Acceptance criteria

1. With at least one row selected, clicking Apply tag… opens the existing `ApplyTagModal` with the selected resource IDs; closing the modal restores the page.
2. Hibernate on a selection clears the selection and shows a toast/notice acknowledging the action.
3. Send to Recommendations navigates to `/recommendations`.
4. Export selected downloads `resources-selected.csv` containing only the selected rows.
5. Manage all views… (in the View dropdown) opens a modal listing the saved views; closing restores the page.

## Quality gates

- Vitest unit tests assert each new behavior (modal opens, navigation occurs, CSV download triggered).
- Manual smoke in mock mode for each control.
- `npm test` passes.
