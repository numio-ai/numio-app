# aws_org_tag_policy table, sync service, daily job, endpoints, conflicts

## Problem statement

Numio is unaware of AWS Organizations Tag Policies, so it cannot surface schema conflicts against its own `tag_policies`. Feature `tag_management` needs read-only ingestion with management-account auto-detect and a conflicts view. Spec §5.4, §6.4, §7.2, §7.4, §8.3.

## Scope

In scope:
- Alembic: create `aws_org_tag_policy` (cols per spec §5.4; unique `(workspace_id, tag_key)`).
- `core/aws_org_tag_policy_service.py`: `sync(session, workspace_id) -> int` (management-account detect per §6.4 via `organizations:DescribeOrganization`; `ListPolicies(TAG_POLICY)` + `DescribeEffectivePolicy`; parse; upsert per tag key; keep full fragment in `raw`). `detect_schema_conflicts(session, workspace_id) -> list[ConflictDescriptor]` per §7.4 (differing `required`, `allowed_values` set diff, case-sensitivity, `missing_in_numio`).
- Daily worker job `aws_org_tag_policy_sync` (24h interval) registered in the worker.
- Endpoints: `GET /aws-org-tag-policy` (viewer+), `POST /aws-org-tag-policy/sync` (admin), `GET /tags/schema/conflicts` (viewer+).
- Schema tab conflicts count badge wired to the conflicts endpoint; `AwsOrgConflictModal` is read-only.

Out of scope:
- Two-way Numio → AWS Org reconciliation (deferred, spec §3).

## Acceptance criteria

A1 (=feature A6). With an AWS Org tag policy in the management account, the daily job populates `aws_org_tag_policy`; `GET /aws-org-tag-policy` returns synced rows; `GET /tags/schema/conflicts` returns conflicts when a Numio rule's `tag_name` matches an Org key but `required`/`allowed_values` differ.
A2. `AWSOrganizationsNotInUseException` ends the sync gracefully (workspace marked non-org), no error surfaced as failure.
A3. Detection picks the connected account whose `aws_account_id == MasterAccountId`.

Notable decisions / deviations:
- **Org calls assume the tag-writer role, not the reader role.** The `organizations:*` permissions live on `NumioTagWriterRole` (§6.1), so detection/sync assume `tag_writer_role_arn`; accounts without it are skipped with zero AWS calls. Org Tag Policy sync therefore requires tag writes enabled on the management account. §6.4 ambiguously said "assume the role"; resolved to the writer role. Spec §6.4 updated.
- **A2 "workspace marked non-org" implemented as a behavioral no-op, not a persistent flag.** On `AWSOrganizationsNotInUseException` the sync ends gracefully (logs INFO, upserts nothing, returns 0, raises no failure). Deliberately did NOT add a `workspaces.is_on_org` column: a persistent flag needs a clear-when-customer-joins-Org lifecycle, and the daily per-account detection is negligible idle work for non-org tenants. A2's "no error surfaced as failure" is satisfied; the "marked" wording is interpreted as behavioral, not stateful.
- **Per-account daily job (not workspace-level-once).** `run_job` fans out per connected account; each invocation runs `_sync_from_account`, which short-circuits to a no-op (zero AWS calls) for accounts that lack the writer role or are not the management account. Avoids N× redundant detection while reusing the runner's per-account isolation (assume-role failure → `RuntimeError` → recorded as that account's failure, others continue).
- **Inline conflicts, not a modal.** The `AwsOrgConflictModal` named in the spec was deleted in the `ia_v2_govern` rebuild. Replaced with a read-only inline section + tab badge matching the rebuilt page's density (advisor-endorsed). Spec §9.1 updated.
- **Source attribution.** The effective policy is a merge of all attached TAG_POLICY documents; synced rows are attributed to the first `list_policies` result for `source_policy_id`/`source_policy_arn`, with the full per-key fragment in `raw`.
