# core/tag_write_service.py — batched RGTA tag writes with action-event audit

## Problem statement

Numio has no code path to write tags to AWS. Feature `tag_management` needs a service that applies single or bulk (≤100) tag changes via `resourcegroupstaggingapi`, records every change in the action-event audit, and never lets one resource failure block others. Spec §6.3, §7.1.

## Scope

In scope:
- `core/tag_write_service.py` with `apply_tag_changes(session, workspace_id, changes, actor, rationale) -> ActionEventResult`. `TagChange = {resource_id, tag_key, value|None}`; `value=None` = remove.
- Flow per spec §7.1: cap 100; load `CloudResource` rows, group by account; assume each account's `tag_writer_role_arn` (must be set); create `audit_action_events` parent (`in_progress`); batch `tag_resources`/`untag_resources` ≤20 ARNs; write one `audit_action_event_items` row per resource×key with before/after/status/error_code/error_message/aws_request_id; recompute summary; set terminal parent status (`success`/`partial_failure`/`failure`) + `completed_at`.
- Parse `FailedResourcesMap`; failures recorded, not raised.
- S3 buckets: read current tags and merge before `PutBucketTagging` (it replaces the whole set) — spec §13.
- Single-resource convenience wrapper for MCP.
- Use the account's stored credentials (not the host credential chain) per dev-runbook convention. Note: the existing `assume_role_for_account(account)` (`core/aws_service.py`) assumes the **reader** `role_arn`. This task must assume the **writer** role at `account.tag_writer_role_arn` instead — add a role-arn parameter/variant rather than reusing the reader helper as-is. The `tag_writer_role_arn` column (added by `tag_writer_cfn_extension`) is non-null only for accounts where tag writes were verified; treat null as "writes disabled" and skip/raise accordingly.

Out of scope:
- HTTP endpoints + risky-write gate (task `tag_apply_api`).
- MCP registration (task `tag_mcp_tools`).

## Acceptance criteria

A1. A single-key change to one resource writes the tag on AWS and produces one parent + one child row with before/after/`aws_request_id`, parent `status=success`.
A2. A bulk change to 50 resources produces one parent + 50 child rows; partial AWS failures yield `status=partial_failure` and per-resource child error rows.
A3. >100 changes raises before any AWS call.
A4. The service commits its own session (cost-records-style commit caveat from dev-runbook).

## Quality gates
