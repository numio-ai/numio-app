# MCP Server

## Prerequisites

- **P3.3 — Cost attribution & cost views API:** Provides cost data that MCP tools wrap.
- **P4.3 — Findings management:** Provides findings data that MCP tools wrap.
- **P6.1 — Recommendations engine:** Provides recommendations data that MCP tools wrap.

## Problem Statement

External AI agents need to interact with Numio programmatically to query cost data, list findings, and get recommendations. The MCP (Model Context Protocol) server provides a standardized tool-based interface that AI agents can use without going through the REST API.

## Scope

**In scope:**
- MCP server exposed at `/mcp` (streamable HTTP) and `/mcp/sse` (SSE transport)
- MCP tools that mirror key REST API capabilities:
  - `get_cost_summary` — total spend with optional date range and dimension filters
  - `get_cost_by_dimension` — spend grouped by a specified dimension
  - `list_findings` — list findings with optional type/severity/status filters
  - `list_recommendations` — list recommendations with optional category/status filters
  - `get_account_status` — list registered AWS accounts with sync status
- Each tool has typed parameters and returns structured data
- MCP tools delegate to the same core business logic as the REST API (via core layer) — no duplicate business logic. Extend the existing MCP server infrastructure (backend/src/numio/mcp/) with production tools. Tool definitions should be shareable with the analytics chat backend (P7.1) where possible, since both use the same underlying core APIs.
- Workspace scoping applies to all MCP tool calls

**Out of scope:**
- MCP tools that trigger state changes (MVP is read-only for MCP)
- Authentication for MCP (uses same auth as REST API)
- Frontend integration with MCP
- MCP resource endpoints (tools only for MVP)

## Acceptance Criteria

1. MCP server responds to tool calls at `/mcp` endpoint
2. MCP server is also accessible via SSE transport at `/mcp/sse`
3. `get_cost_summary` returns accurate cost data matching what the REST API returns
4. `get_cost_by_dimension` returns correctly grouped cost data
5. `list_findings` returns findings with correct filtering
6. `list_recommendations` returns recommendations with correct filtering
7. `get_account_status` returns account list with sync status
8. All tools return structured data (not free-text)
9. MCP tools use the same core logic as REST API — no divergence in results
10. MCP tool calls return data scoped to the authenticated workspace — no cross-workspace data leakage
