# Align `numio-dev.sh` `logs` Command With `docker logs` Semantics

## Date
2026-04-16

## Context

`scripts/numio-dev.sh logs [component...]` is the developer-facing wrapper over `docker compose logs` (for infra containers) and `tail -f` (for native app log files). It is defined in `scripts/tools/dev.sh` as `dev_logs()`, dispatched from `scripts/numio-dev.sh`, and referenced in `docs/dev-runbook.md` and `docs/design/scripts-spec.md`.

Today's behavior has three rough edges compared to what a developer expects when they reach for a `log` command:

1. The subcommand is named `logs` (plural), but other common tools the developers use (`docker log`, `kubectl logs` as a single command, `journalctl`, `git log`) lead to muscle-memory typing `log`. Cursor users on this project already type `log` and get "Unknown command".
2. It **always follows** the stream (`docker compose logs -f` / `tail -f`). There is no way to get "the last page of logs and exit" from this command. Developers fall back to raw `docker logs <container> --tail N` or `tail -n N .numio/logs/<c>.log`, which defeats the purpose of the wrapper and requires them to know container names.
3. For infra containers, the underlying `docker logs` / `docker compose logs` writes app output on **stderr**. When a developer pipes the output into `grep` (e.g., `./scripts/numio-dev.sh logs worker | grep "03:22:53"`), stderr bypasses the pipe and shows up unfiltered on the terminal, so the command appears to "ignore `grep`". Users currently work around this with `2>&1`, which is easy to forget.

Related files:
- `scripts/numio-dev.sh` — command dispatcher (case `logs)` → `dev_logs`).
- `scripts/tools/dev.sh` — `dev_logs()` implementation (`_compose logs -f`, `tail -f`).
- `docs/dev-runbook.md` — user-facing examples of `logs`.
- `docs/design/scripts-spec.md` — CLI contract for the dev/ctl scripts, including test cases.

## Problem

The current `logs` command does not behave the way developers expect from a log CLI and silently loses output when combined with `grep`:

1. **Wrong name.** `logs` disagrees with peer tools (`docker logs`, `git log`, `journalctl`, `kubectl logs` — arguably the one odd one out; but note our own `docker logs` invocation is singular-ish in spelling). The typed-from-memory command is `log`; today that prints "Unknown command: log".
2. **No non-follow mode.** The command has no way to say "show me the last page and exit". Running `./scripts/numio-dev.sh logs backend | head` hangs on the tail, and piping to `grep` on a still-running stream never terminates.
3. **Silent stderr leak.** Because `docker compose logs` (and in turn `docker logs`) writes container logs on stderr, `./scripts/numio-dev.sh logs worker | grep PATTERN` filters only the (empty) stdout stream, and all the actual log lines go straight to the terminal. The user observes "grep doesn't filter anything", which is confusing and wastes time. The fix (`2>&1 | grep`) is non-obvious and easy to forget.

**Evidence:**
- `scripts/tools/dev.sh` `dev_logs()` calls `_compose logs -f` and `tail -f` unconditionally.
- `scripts/numio-dev.sh` `case` statement accepts `logs` but not `log`.
- Terminal session on 2026-04-16 where `docker logs numio-worker | grep "03:22:53,932"` appeared to show every line — same root cause applies to `numio-dev.sh logs` because it delegates to the same stream topology.

**Impact:** Every developer using the wrapper hits at least one of these three issues regularly. The stderr leak is particularly dangerous because the command *appears* to work — it just silently shows the wrong thing.

## Goals

Modify `scripts/numio-dev.sh` (and its helper in `scripts/tools/dev.sh`) so the log command:

1. Is invoked as **`log`** (singular).
2. **Defaults to non-follow**: prints the last page of logs and exits with code 0.
3. Supports **`-f` / `--follow`** to restore the current "follow the stream" behavior.
4. **Merges stderr into stdout** before the command's output is produced, so that a single `| grep PATTERN` filters every log line without requiring `2>&1`.
5. Continues to cover the same components as today (`backend`, `frontend`, `worker`, `postgres`, `valkey`, `infra`, `all`) with the same component-resolution rules.
6. Is documented consistently in `docs/dev-runbook.md` and `docs/design/scripts-spec.md`, including the new default behavior and the `--follow` flag.

## Non-goals

- Do **not** change `scripts/numio-ctl.sh`'s `logs` subcommand in this task. That script has a separate operator-facing contract and is owned by the ops-runbook rewrite track. If the same rationale applies there, capture a follow-up task; do not expand scope here.
- Do **not** change log file locations, rotation, or the native-vs-container logging topology in `.numio/logs/`.
- Do **not** add structured-log features (JSON mode, filters by level, timestamps-only, etc.). Scope is name, follow flag, and stderr redirection.
- Do **not** redesign the component model or argument parser beyond what is necessary to add `-f|--follow`.

## Constraints & assumptions

- **Constraint:** The new command must be `log` (singular). The user has explicitly specified this spelling.
- **Constraint:** Default behavior must **not** follow. A developer running `./scripts/numio-dev.sh log backend` must see output and get their prompt back. This matches `git log` / `journalctl` (without `-f`) semantics, not `tail -f`.
- **Constraint:** `./scripts/numio-dev.sh log <...> | grep X` must filter every log line produced by the command — no lines may bypass the pipe via stderr — without the user supplying `2>&1`.
- **Assumption:** "Last page" is a reasonable default, implementable as `--tail=200` (or similar) for `docker compose logs` and `tail -n 200` for native app log files. Exact line count is an implementation detail; pick a value that fits a typical terminal and document it. If the user has a strong preference, capture it in the PR discussion.
- **Assumption:** The help text (`usage()` in `numio-dev.sh`) and the `Lifecycle Commands` table are the canonical source for the subcommand name; both must be updated.
- **Open question — backward compatibility for `logs`:** decide before implementation whether `logs` should (a) be removed, (b) remain as an undocumented alias for `log` that prints a deprecation hint, or (c) remain as a fully documented synonym. Default recommendation: **(b) hidden alias with a one-line deprecation warning**, mirroring how `dev` is kept as a hidden alias for `run` today. Confirm with the user at implementation time; do not decide in this task.

## Acceptance criteria

1. **Command is `log`.** `./scripts/numio-dev.sh log` (with or without component arguments) is accepted. The `usage()` output and the `Lifecycle Commands` block in `scripts/numio-dev.sh` list `log` (not `logs`) as the command name.
2. **Default is non-follow.** `./scripts/numio-dev.sh log backend` prints the last page of backend logs and returns to the shell prompt (exit code `0`) within a couple of seconds, without requiring Ctrl-C. The same holds for `log` with no arguments (all components) and for any component in `backend | frontend | worker | postgres | valkey | infra | all`.
3. **`-f` / `--follow` restores streaming.** `./scripts/numio-dev.sh log -f backend` and `./scripts/numio-dev.sh log --follow backend` behave like today's `logs backend` — the stream is followed until the user sends Ctrl-C. The flag is accepted before or after the component list.
4. **Grep works without `2>&1`.** Running `./scripts/numio-dev.sh log worker | grep NEVER_MATCHES` produces no output on the user's terminal (neither on stdout nor on stderr of the pipeline). Conversely, `./scripts/numio-dev.sh log worker | grep <a string known to be in recent logs>` matches all log lines containing that string, including lines that `docker logs` would have emitted on stderr.
5. **All component classes covered.**
   - Infra containers (`postgres`, `valkey`): use `docker compose logs [--tail=N | -f]` and redirect stderr into stdout inside the wrapper.
   - Native app log files (`backend`, `frontend`, `worker` when running in background): use `tail -n N` by default, `tail -f` with `--follow`. Stderr of `tail` is also redirected into stdout for consistency.
   - Mixed (`all`, or `infra` + app): both streams' output is combined into a single stdout stream suitable for piping to `grep`.
6. **Help text matches reality.** `./scripts/numio-dev.sh --help` documents:
   - The command name `log`.
   - The `-f` / `--follow` flag and that the default is non-follow.
   - That output is safe to pipe through `grep` / `head` / `less` without `2>&1`.
7. **Docs updated.**
   - `docs/dev-runbook.md`: every `./scripts/numio-dev.sh logs ...` example is updated to `./scripts/numio-dev.sh log ...`, and at least one example of `-f` and one of piping into `grep` are present.
   - `docs/design/scripts-spec.md`: section 4.4.4 (logs) is renamed/updated to describe `log`, the new default, the `--follow` flag, and the stderr-merging behavior. Test cases referencing `logs` are updated.
8. **No regressions in other subcommands.** `run`, `stop`, `status`, `restart`, `rebuild`, `migrate`, `health`, `init`, `build`, and the hidden `dev` alias continue to behave as they do today.
9. **Backward-compat decision is implemented consistently.** Whichever of (a)/(b)/(c) is chosen for the old `logs` name, the choice is reflected in the code and the docs (either fully absent, or kept with a clear note).

## Validation steps

1. **Name check:**
   ```bash
   ./scripts/numio-dev.sh log --help | head
   ./scripts/numio-dev.sh log            # no-follow, exits
   ./scripts/numio-dev.sh log backend    # no-follow, exits
   ```
   Each returns to the prompt without Ctrl-C and prints recent log lines.
2. **Follow check:**
   ```bash
   ./scripts/numio-dev.sh log -f backend      # streams; Ctrl-C exits cleanly
   ./scripts/numio-dev.sh log --follow infra  # streams postgres+valkey
   ```
3. **Grep-without-redirect check:**
   ```bash
   ./scripts/numio-dev.sh log worker | grep -c ''     # non-zero count
   ./scripts/numio-dev.sh log worker | grep __NOPE__  # no output at all
   ./scripts/numio-dev.sh log -f worker | head -n 20  # exits after 20 lines, no leaked stderr output
   ```
4. **All-components check:** `./scripts/numio-dev.sh log all` prints a bounded tail from each running component and exits.
5. **Docs lint:**
   ```bash
   grep -nE 'numio-dev\.sh +logs\b' docs/dev-runbook.md docs/design/scripts-spec.md
   ```
   Returns no hits (outside of an explicit "renamed from `logs`" note, if the backward-compat decision calls for one).
6. **Backward-compat behavior matches the agreed choice.**
   - Option (a) removed: `./scripts/numio-dev.sh logs` → "Unknown command".
   - Option (b) hidden alias: `./scripts/numio-dev.sh logs backend` works and prints a deprecation hint on stderr; does not appear in `--help`.
   - Option (c) documented alias: appears in `--help` and works identically to `log`.

## Risks & rollback

- **Risk — muscle memory regression.** Developers who have typed `logs` for months will need to relearn. Mitigation: keep `logs` as a hidden alias with a deprecation hint for at least one release (default recommendation), and call out the rename in the dev-runbook change.
- **Risk — `--tail=N` default is wrong.** Too-small `N` hides useful context; too-large `N` floods the terminal. Mitigation: pick a sensible default (≈200 lines) and document it; accept a future follow-up to make it configurable if needed.
- **Risk — stderr merging hides real errors from the wrapper itself.** The wrapper's own diagnostics (e.g., `log_warn "$c is running in a foreground terminal"`) must remain on the wrapper's stderr; only the *child process*' stderr (the one that today carries container log output) should be merged into stdout. Mitigation: apply the redirection only to the `docker compose logs` / `tail` invocations, not to the whole function.
- **Rollback:** revert the commit. The `logs` subcommand and its current follow-always behavior return with no state migration needed.
