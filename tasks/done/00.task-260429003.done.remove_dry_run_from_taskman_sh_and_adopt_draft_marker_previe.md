# Remove --dry-run from taskman.sh and adopt draft-marker preview in skills

## Problem statement

`scripts/taskman.sh` exposes a `--dry-run` flag on `new feature` and `new task`
that prints the full would-be path and composed file body to stdout instead of
writing to disk. Three skills use it as a "last-chance preview" before the real
write — `create-task`, `create-feature`, `codebase-review`.

In practice the mechanic harms the workflow it was meant to support:

- The composed file body (often 40–120 lines) is emitted as tool output, lands
  in the chat transcript, and consumes a meaningful number of tokens twice —
  once for the dry-run and again for the real write.
- The user is forced into a redundant approval round-trip for content they have
  already shaped in the dialog.
- The flag's branching logic in `taskman.sh` adds maintenance surface for no
  durable benefit.

A simpler preview is available: write the file directly into `backlog/`, mark
it as a draft via a YAML field, re-read it from disk, show it to the user, and
clear the draft marker on approval (or delete the file on rejection).

## Scope

In scope:

- `scripts/taskman.sh`: remove the `--dry-run` flag, its `dry_run` local
  variable, the dry-run branches in both `cmd_new_feature` and `cmd_new_task`,
  and every reference in the script's header comments and `cmd_help` output.
- New YAML field on freshly created task and feature files — name to be
  decided during implementation, e.g. `draft: true` — written by `taskman.sh
  new …` and cleared by a follow-up `taskman.sh` invocation once the skill
  confirms user approval. The field is informational only; it does not become
  a fourth lifecycle state and `status` remains `backlog | active | done`.
- `taskman.sh validate`: accept files with or without the draft field; do not
  treat it as an error or a warning under either condition.
- `.claude/skills/create-task/SKILL.md`,
  `.claude/skills/create-feature/SKILL.md`,
  `.claude/skills/codebase-review/SKILL.md`: replace the "run with
  `--dry-run`, then rerun without it" guidance with the new draft-marker flow
  — write directly, re-read from disk, show to user, finalise on approval,
  delete on rejection.
- `.claude/rules/task-management.md`: drop `--dry-run` from the documented
  command surface and document the draft-marker workflow as the canonical
  preview mechanism.

Out of scope:

- Adding a fourth lifecycle state (`draft` as a peer of `backlog/active/done`).
- Any changes to `move`, `feature close`, `list`, or `validate` beyond the new
  field's tolerance.
- Refactoring unrelated taskman behaviour.

## Acceptance criteria

1. `grep -rn "dry-run\|dry_run" scripts/taskman.sh .claude/skills/ .claude/rules/`
   returns zero matches.
2. `./scripts/taskman.sh help` output contains no mention of `--dry-run`.
3. `./scripts/taskman.sh new task --title "x" --dry-run </dev/null` exits
   non-zero with an unknown-flag error.
4. Running `/agn:create-task task "<title>"` end-to-end produces:
   - a file under `tasks/backlog/` with `status: backlog` and the draft
     marker present during the review phase,
   - the marker cleared after the user approves the preview,
   - a deleted file if the user rejects.
5. `/agn:create-feature` and `/agn:codebase-review` follow the same flow with
   the same disk-write semantics.
6. `./scripts/taskman.sh validate` is clean on a repository containing tasks
   in both states (marker present, marker absent).

## Quality gates

- `./scripts/taskman.sh validate` returns clean.
- `./scripts/taskman.sh help` reviewed manually; no stale `--dry-run` text.
- Manual end-to-end run of `/agn:create-task task "<probe>"`: confirm file is
  written, re-read, shown, finalised on approval (marker cleared), deleted on
  rejection.
- Repeat the manual end-to-end run for `/agn:create-feature` (one feature +
  at least one child task) and `/agn:codebase-review` (single finding).
- Spot-check `.claude/rules/task-management.md` to confirm the documented
  surface matches the new behaviour.

## Risks and rollback

- Risk: in-flight task drafts created with the old `--dry-run` flag during the
  changeover get confused by the new flow. Mitigation: this is a single-user
  local repo; no in-flight drafts to migrate.
- Rollback: revert the change as a single commit. The draft-marker field is
  optional, so files written under the new flow remain valid against the old
  validator.

8. Updated `.claude/rules/task-management.md` Tooling section: removed `--dry-run`, added `finalize`/`discard`, and added a *Draft preview workflow* subsection explaining the marker is informational and not a fourth lifecycle state.
9. Verified all acceptance criteria pass (grep for dry-run is zero across the four target paths; help text is clean; `--dry-run` is rejected; end-to-end probe — create → finalize cleanly clears marker; create → discard removes file; `taskman.sh validate` is green).

### Changes made
- `scripts/taskman.sh` — flag removal, helper added, two new commands, template update, help update.
- `scripts/tests/taskman_test.sh` — test rework.
- `.claude/skills/create-task/SKILL.md`, `.claude/skills/create-feature/SKILL.md`, `.claude/skills/codebase-review/SKILL.md` — workflow updates.
- `.claude/rules/task-management.md` — tooling section + new draft-workflow subsection.

### Notable decisions
- Implemented the user-chosen "informal" interpretation: `draft: true` is an optional YAML field, not a fourth value of `status`. `validate` accepts files with or without the marker (no rule changes needed since validate only checks `status`, `kind`, `feature`).
- `discard` refuses to delete files that lack `draft: true`, preventing accidental destruction of finalized work.
- `finalize` is idempotent — running it on a file without the marker logs "Already finalized" and exits 0.
- `move` was deliberately left untouched; the skill flow finalizes before any `move`, so the marker is gone by then.
