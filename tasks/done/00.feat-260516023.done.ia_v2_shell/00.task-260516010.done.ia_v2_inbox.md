# IA v2 Inbox — rename Feed, supply mock unread-count hook

## Problem statement

The Feed page (`/feed`, `FeedPage.jsx`) is positioned as a passive list. In IA v2 it becomes the default landing surface and the user's work queue — renamed Inbox, promoted to the top of the sidebar, with an unread count that signals "work for you". The page content stays roughly the same; the framing changes.

## Scope

In scope:
- Move `pages/Feed/FeedPage.jsx` to `pages/Inbox/InboxPage.jsx`; update imports.
- Add route `/inbox` (legacy `/feed` route is removed in `ia_v2_routes`).
- Update page title and breadcrumb to "Inbox" via the top-bar page-label map.
- Page header subtitle reads "Work queue · {unread} need triage" — matches the mock.
- Create `hooks/useInboxUnreadCount.js` (or `.ts`) returning a number. Initial implementation returns a static value (e.g. 11) wrapped in `useMemo`. Task `ia_v2_be_inbox_badge` will replace the body with a real fetch.

Out of scope:
- Backend unread-count API — `ia_v2_be_inbox_badge`.
- Per-finding triage UI overhaul — only frame the page; content stays.
- "Triage with Numio" CTA chat-prefill wiring — leave the button visible, no chat-prefill flow.

## Acceptance criteria

A1. Visiting `/inbox` renders the renamed page; the breadcrumb says "Inbox".

A2. The page H1 is "Inbox"; the subtitle text includes the unread count returned by the hook.

A3. `useInboxUnreadCount()` is a hook returning a number; current implementation returns a static value. The hook lives in a single file that `ia_v2_be_inbox_badge` can later replace with a real fetch — no other changes needed in consumers.

A4. The sidebar Inbox badge reads from the same hook.

A5. No import paths in `frontend/src/` reference `pages/Feed/FeedPage`.
