# Mock/real switch and API dispatch seam

## Problem statement

The frontend talks to the backend through 9 API modules in `frontend/src/api/`. Each module defines its own near-duplicate `request()` fetch helper (with three drifted error conventions and a GET-only variant in `dashboard.js`), and components import API functions directly. Today the UI cannot run without a live backend: every page that calls these functions fails when no backend is reachable. The team needs to demo and develop the full UI from synthetic data with zero backend, and flip to the real backend by one build-time setting — with no change at any component call site.

This task builds the foundation: a single shared API client with the mock/real decision inside it, plus the mock-dispatch plumbing, proven on a thin vertical slice. Authoring the per-domain mock handler files for all modules (`endpoint_coverage`) and the synthetic data (`synthetic_data_*`) are sibling tasks that depend on this foundation. See the linked spec `docs/frontend/mock-backend-spec.md` §3.

## Scope

In scope — consolidation:

- Create `frontend/src/api/client.js` exporting one `request(path, options)` with a minimal option surface: `method` (default `GET`), `headers` (merged over the default `Content-Type: application/json`), `body`, and `graceful` (resolve `null` on error instead of throwing). Behavior: resolve `BASE` from `VITE_API_URL` once; `credentials: "include"`; `null` on HTTP 204; otherwise return parsed JSON; throw `ApiError` on non-2xx.
- A single `ApiError extends Error` carrying `status`, `detail`, `errorCode`, `body`, replacing the three current error styles. Keep `DataExplorerError` exported (as a subclass of `ApiError`) so `DataExplorerPage.jsx` keeps working.
- Keep `gracefulRequest(path, options)` as a thin wrapper.
- Replace all 9 local `request()` helpers with `import { request } from "./client"`. Convert `dashboard.js`'s GET-only `request` to the shared one and refactor its ~14 inline-`fetch` write functions to call `request(path, { method, body })`.

In scope — the switch and seam:

- Add the `VITE_API_MODE` build-time switch (values `mock` | `real`, default `real`) via a `define` block in `frontend/vite.config.js` (per spec §2.1; an unset Vite var is not statically replaced and breaks tree-shaking). Remove the `stripMocksInProd` plugin.
- Inside `request()`, the one mock/real branch: real mode does today's `fetch`; mock mode dispatches to the mock handler registry.
- The mock-dispatch plumbing: a handler registry keyed by `METHOD` + path with a small matcher for `:id`-style segments; the in-memory write store scaffold (`src/api/mock/store.js`); a shared latency wrapper. A missing handler in mock mode throws `ApiError(404)`.
- Prove the whole path on a thin vertical slice: one domain's handlers + minimal fixtures, rendering in mock mode with no backend.

Out of scope (sibling tasks):

- The per-domain mock handler files for all 9 modules — `endpoint_coverage`.
- The synthetic data set — `synthetic_data_core/cost/governance/platform`.
- Vitest/Puppeteer wiring — `test_integration`.
- Documentation — `docs_env_example`.
- The `params`/`json` API-client DRY unification across call sites — separate follow-up task `api_client_dry_refactor`. Leave call sites' existing query/body construction untouched.

## Acceptance criteria

1. Setting `VITE_API_MODE=mock` makes the chosen slice serve data from mock handlers with no backend reachable; `real` (or unset) makes it call the backend. The choice is fixed at build time; no runtime toggle exists.
2. Component call-site imports and the exported function names/signatures of every API module are unchanged (grep-verifiable: same import paths, same exported names, same argument lists). Module file *contents* change (they import the shared client; `dashboard.js` writes are refactored) — call sites do not.
3. The 9 local `request()` helpers are gone; every module imports `request` from `src/api/client.js`. `ApiError` is the single error type; `DataExplorerError` remains exported as its subclass. `dashboard.js`'s 14 inline-`fetch` writes route through the shared `request()`.
4. The mock/real branch exists only inside `request()`. In mock mode a request with no matching handler throws `ApiError(404)`, so `gracefulRequest` resolves to `null` (matching a missing real endpoint).
5. Mock responses pass through the shared latency wrapper, so a loading state renders before data appears.
6. `stripMocksInProd` is removed and the `define` block added. `cd frontend && npm run build` succeeds with `VITE_API_MODE=mock` and with `VITE_API_MODE` unset; a real build contains no `src/api/mock/` modules (tree-shaken out).
7. With `VITE_API_MODE=mock` and no backend running, the chosen slice renders from mock data via the dev server.
8. The slice demonstrates the per-domain handler pattern: adding a domain to mock mode means adding one handler file under `src/api/mock/`, with no change to the client or registry core.

## Quality gates

- `cd frontend && npm test` passes.
- `cd frontend && npm run build` succeeds in BOTH modes: once with `VITE_API_MODE=mock` and once with `VITE_API_MODE` unset/real. This dual-mode build is the discriminating gate.
- Real-build audit: build with the default (real) mode and confirm no `src/api/mock/` module or synthetic-data file is present in the output (grep the build/`dist`).
- Manual check: with `VITE_API_MODE=mock` and no backend process running, start the dev server (`./scripts/numio-dev.sh run frontend`) and confirm the chosen slice renders from mock data with a visible loading state on first paint.

## Constraints and assumptions

- This is the foundation task; the data tasks and `endpoint_coverage` depend on it. Use minimal stub fixtures for the slice — full synthetic data is the `synthetic_data_*` tasks.
- Unifying the three error conventions changes the thrown message text for `inbox.js`/`tagGovernance.js` (today `"API <status>: <body>"`). Verified safe as of 2026-05-27: no consumer asserts on that text (`ErrorBoundary` and `DataExplorerPage` only display `error.message`). `ApiError` preserves `status`/`detail`/`errorCode`.
- No API module injects custom auth/API-key headers; all use cookie auth (`credentials: "include"`). The corrected header merge is therefore behaviorally inert for current callers.
- Every success response in the codebase is JSON (204 → `null`); there are no blob/text/multipart responses, so the client parses JSON unconditionally on success.
- `getNotificationStreamUrl` (SSE) and `getCfnTemplateDownloadUrl` (download link) do not call `request()` and bypass the seam — see spec §4.5; not handled here.

## Summary

### Steps completed
1. Built the shared client `frontend/src/api/client.js`: one `ApiError extends Error` (status/detail/errorCode/body), one `request(path, options)` with correct header merge, `credentials: "include"`, 204→null, JSON parse, throw `ApiError` on non-2xx; `gracefulRequest` thin wrapper.
2. Put the mock/real decision inside `request()` as a single branch on `import.meta.env.VITE_API_MODE`, via a **gated dynamic `import("./mock/registry.js")`** so the mock subtree is dead code in a real build (chosen over a package-wide `sideEffects: false`, which is a footgun).
3. Built the mock-dispatch plumbing: `mock/matcher.js` (`:id` path matching), `mock/registry.js` (`dispatchMock`, handler list, `ApiError(404)` on no match), `mock/store.js` (in-memory session store + `reset()`), `mock/latency.js` (`withLatency` + `setMockLatency` for tests).
4. Consolidated all 9 API modules onto the shared client — removed every local `request()` helper. `dataExplorer.js` keeps `DataExplorerError` (now `extends ApiError`) and rethrows so `DataExplorerPage` is unchanged. Converted `dashboard.js`'s 14 inline-`fetch` writes to `request(path, { method, body })` (kept `JSON.stringify` at call sites per spec §8).
5. Vite: removed the `stripMocksInProd` plugin; added the `define` that compiles an unset `VITE_API_MODE` to the literal `"real"`.
6. Proved the seam on a vertical slice (inbox domain `mock/inbox.js` + minimal `mock/auth.js` so the app authenticates), with unit tests for matcher, registry dispatch (read + write-through-store + 404), and the client.

### Changes made
- New: `frontend/src/api/client.js`, `frontend/src/api/mock/{registry,matcher,store,latency,inbox,auth}.js`, tests `client.test.js` + `mock/{matcher,registry}.test.js`.
- Modified: all 9 modules in `frontend/src/api/` (helper → import); `frontend/vite.config.js` (plugin removed, `define` added). `dashboard.js`/`onboarding.js` retain `BASE` only for the SSE/download URL builders.

- DCE mechanism: gated dynamic import (not `sideEffects: false`), per reviewer guidance and verified by the dist audit.
- Pre-existing dead code left untouched: the legacy `frontend/src/mocks/*` static fixtures are unchanged (the `synthetic_data_*` tasks own their migration).
