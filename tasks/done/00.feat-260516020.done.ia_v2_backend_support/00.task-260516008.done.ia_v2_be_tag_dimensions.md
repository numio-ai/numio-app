# Backend — Tag-as-dimension for cost/usage queries

# Backend — Tag-as-dimension for cost/usage queries

## Problem statement

The IA v2 Usage page exposes any tag key as a Group-by or Filter dimension. The current cost/usage query layer only supports a fixed set of platform dimensions.

## Scope

In scope:
- Extend the `cost_records` query layer to support `group_by=tag:<key>` and `filter=tag:<key>:<value>`.
- Tag values are read from `resource_tags` joined to `cost_records` via `arn` or `line_item_resource_id`.
- Untagged spend is exposed as a synthetic "Untagged" bucket per group-by query.
- Extend the existing usage endpoint (or add a sibling endpoint) to accept tag-dimension parameters.
- The tag-schema source for the frontend dropdown is the existing `GET /tags/schema` from `tag_management` — no new schema endpoint here.

Out of scope:
- Multi-tag composite group-by (`team + env`) — later.
- Materialized rollups — performance follow-up if needed.

## Acceptance criteria

A1. Calling the usage endpoint with `group_by=tag:cost-center` returns one bucket per cost-center value found in `resource_tags` for the requested period.

A2. Resources with no value for the group-by tag fall into a bucket labeled `Untagged`.

A3. Filtering by `tag:env:production` reduces the result to only resources with that tag value.

A4. Combining `group_by=tag:cost-center` and `filter=tag:env:production` produces correct buckets.

## Summary

### Steps completed

Scaffold-only per option 2:

1. Built `schemas/ia_v2_usage.py` — `UsageResponse` with `total`, `delta_pct`, `forecast`, `series[]`, `breakdown[]`, `untagged_spend`, `tag_keys_available`, `platform_dims_available`. Enums for `UsageScope` (cloud/ai) and `UsageRange` (7D/30D/MTD/QTD/YTD).
2. Built `api/ia_v2_usage.py` with two endpoints:
   - `GET /usage?scope=&range=&group_by=` — returns chart series + breakdown for the picked group-by. Series include a first-class "Untagged" entry when applicable.
   - `GET /usage/tag-keys` — returns the schema's tag-key vocabulary for the group-by picker.
3. Wired router into `main.py`.
4. Wrote 6 pytest cases: default response shape (cloud / 30D / tag:cost-center), AI scope hides forecast, range param changes series length, invalid range → 422, tag-keys endpoint, available-dimensions discovery.

### Changes made

- New: `schemas/ia_v2_usage.py`, `api/ia_v2_usage.py`, `tests/test_ia_v2_usage.py`.
- Modified: `main.py` — added import + include_router.

### Notable decisions or deviations

- **Mock series generated synthetically** with deterministic drift/phase per series (no `random`) so the response is stable for tests + screenshots.
- **`tag_keys_available` returned in every response** so the frontend can populate the group-by picker without a separate request. Mirrors `/usage/tag-keys` for explicit fetch.
- **`range` alias mapped to Python keyword conflict**: query param `range` accepted via `Query(alias="range")` because `range` is a Python builtin; internal variable is `range_`.
