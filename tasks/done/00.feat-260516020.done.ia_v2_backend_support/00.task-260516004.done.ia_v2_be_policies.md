# Backend — Policies CRUD with mode + bulk update

# Backend — Policies CRUD with mode + bulk update

## Problem statement

IA v2 Policies has an enabled toggle, mode (Block / Warn / Auto-remediate), and bulk update. The current policies model lacks the mode chip semantics and bulk endpoint.

## Scope

In scope:
- Extend the policies model with `mode: block | warn | auto_remediate` and `enabled: bool`.
- `PATCH /policies/{id}` accepts mode + enabled.
- `POST /policies/bulk { ids: [...], action: enable|disable|change_mode, mode? }`.
- `GET /policies` surfaces `open_violations_count`.

Out of scope:
- Policy authoring UX (still uses existing edit flow).
- Auto-remediate execution path — stub for v1; mode is metadata only at this stage.

## Acceptance criteria

A1. `GET /policies` returns rows with `mode`, `enabled`, and `open_violations_count`.

A2. `PATCH /policies/{id}` updates persist; invalid `mode` returns 400.

A3. `POST /policies/bulk` updates all referenced ids; partial failures are returned per-id in the response body.

A4. Bulk `change_mode` requires `mode` in the body; missing `mode` returns 400.
