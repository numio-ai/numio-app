# Backend — Budgets CRUD with pacing metadata

# Backend — Budgets CRUD with pacing metadata

## Problem statement

IA v2 Budgets shows per-team cards with pacing ticks and ahead/behind annotations. The current Budgets backend does not expose expected-by-day spend or per-team grouping consistent with the frontend cards.

## Scope

In scope:
- `budgets` table (id, workspace_id, name, scope_query_json, period: monthly|quarterly, amount, status_threshold_pct, owner_user_id, created_at).
- Endpoint: `GET /budgets` returns per-budget current spend + `expected_at_today_pct` + status (over|at_risk|on_track).
- `POST /budgets`, `PATCH /budgets/{id}`, `DELETE /budgets/{id}`.
- Per-budget burn-down: `expected_at_day_N = amount * (N / period_days)`; comparison emits ahead/behind percentage points.
- Status derives from current_spend vs amount and current_spend vs expected_at_today using `status_threshold_pct` (configurable, default ±10pp).

Out of scope:
- Forecasting (linear expected-by-day for v1).
- Budget alerts / notifications.

## Acceptance criteria

A1. `GET /budgets` returns rows shaped to drive the cards: `current_spend`, `amount`, `expected_at_today_pct`, `ahead_behind_pp`, `status`.

A2. CRUD endpoints work; AuthZ: owner can write, workspace members can read.

A3. Status derivation: `over` when `current_spend > amount`; `at_risk` when `current_spend > expected_at_today_pct * amount * (1 + threshold)`; `on_track` otherwise.

A4. Status edge cases tested: exactly at amount, exactly at expected, above amount, below expected by threshold.
