# Activate the dormant Cognito identity backend

## Problem statement

Spec R1 mandates a pluggable identity backend. The Cognito implementation exists in code but is dormant. Activating it requires environment configuration, code-path testing, and an enterprise-friendly first-admin path (existing Cognito users vs. fresh Numio install).

## Scope

In scope:
- Activate `IDENTITY_BACKEND=cognito`.
- Reconcile `users` table with the Cognito user pool.
- Map admin role to a Cognito group.
- Define enterprise-onboarding flow when Cognito users already exist.

Out of scope:
- Anything specific to the native backend.
- SAML / OIDC federation.

## Acceptance criteria

- With `IDENTITY_BACKEND=cognito`, sign-in routes through Cognito and returns the same session cookie as native.
- A Cognito admin can manage users via the Numio UI or via the Cognito console; both stay consistent.
- `users.role` mirrors Cognito group membership.

## Quality gates

- Integration tests against a test Cognito user pool.
- Deferred until a customer engagement requires it.
