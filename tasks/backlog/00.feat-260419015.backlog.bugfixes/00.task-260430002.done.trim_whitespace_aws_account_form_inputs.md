## Problem statement

When a user configures an AWS account and the S3 bucket name contains a leading space (e.g. `" numio-cost-info"`), validation during the "Test connection" step fails with:

> List CUR objects in S3: Unexpected error: Parameter validation failed: Invalid bucket name " numio-cost-info": Bucket name must match the regex ...

The space is invisible in the input field, easy to introduce by accident (paste from a doc, trailing newline, etc.), and the error message from boto3 is cryptic for a non-technical user. The fix is to strip leading and trailing whitespace from all AWS account string inputs on change, and to warn the user if an embedded (mid-string) space is detected.

## Scope

**In scope:**
- Strip leading and trailing whitespace (`.trim()`) from all string inputs in the AWS account form in two components:
  - `frontend/src/pages/Settings/Integrations.jsx` — `updateField` at line 109
  - `frontend/src/components/onboarding/GuidedOnboarding.jsx` — `updateField` at line 172–173
- Show an inline warning when the trimmed value still contains a space (embedded space, not a leading/trailing one), because embedded spaces are also invalid in most AWS identifiers (bucket names, role ARNs, account IDs).

**Out of scope:**
- Backend validation changes (the fix is defensive UX; the backend already rejects invalid values).
- Other settings forms unrelated to AWS account configuration (Workspaces, People, API tokens).
- `ChatOnboarding.jsx` input handling (assess separately; it submits via chat, not a form).

## Implementation notes

Both components use an `updateField` helper that sets state from `e.target.value`. The trim should happen there:

**Integrations.jsx (line 109):**
```
// before
const updateField = (field) => (e) => setForm({ ...form, [field]: e.target.value });

// after
const updateField = (field) => (e) => setForm({ ...form, [field]: e.target.value.trim() });
```

**GuidedOnboarding.jsx (lines 172–173):**
```
// before
const updateField = (key) => (e) =>
  setForm({ ...form, [key]: e.target.value });

// after
const updateField = (key) => (e) =>
  setForm({ ...form, [key]: e.target.value.trim() });
```

For the embedded-space warning: after trimming, if the value contains a space, show a small inline message below the field (e.g. *"This value contains a space — AWS identifiers do not allow spaces."*). Use the same styling as existing validation messages in the form.

The fields most sensitive to this issue (and where the warning is most valuable): `cur_s3_bucket`, `role_arn`, `aws_account_id`, `cur_s3_prefix`, `cur_report_name`.

### Notable decisions

- `hasEmbeddedSpace` checks `/\s/.test(v.trim())` rather than `/\s/.test(v)`. With trim already applied at input time, raw `/\s/` would still match a transient leading/trailing space the user just typed; trimming inside the helper makes the warning fire only on truly embedded whitespace, matching the user-facing intent.
- Trim happens on every keystroke (not on blur), per the task's implementation notes. Side effect: a user typing `"foo "` then more chars will see the trailing space removed instantly. Acceptable trade-off given AWS identifiers do not allow trailing whitespace anyway.
- For `GuidedOnboarding.jsx` the warning was added to the five fields the task called out as "most sensitive" rather than every input. Other fields (label, region, alias, etc.) are either pattern-validated already or low-risk.
