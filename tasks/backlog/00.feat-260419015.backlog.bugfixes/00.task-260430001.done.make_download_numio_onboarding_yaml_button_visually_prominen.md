# Make Download numio-onboarding.yaml button visually prominent

## Problem statement

The "Download numio-onboarding.yaml" button in the onboarding wizard uses the `btn--ghost` class (white background, light shadow), making it easy to overlook against the card background. It is a primary action in the CloudFormation setup flow and should stand out clearly.

The same button appears in `ChatOnboarding.jsx` ("Download YAML") with the same low-contrast styling.

## Scope

**In scope:**
- Change the button class from `btn--ghost btn--sm` to `btn--primary btn--sm` in two files:
  - `frontend/src/components/onboarding/GuidedOnboarding.jsx` line 543 (`data-testid="guided-download-url"`)
  - `frontend/src/components/onboarding/ChatOnboarding.jsx` line 330 (`data-testid="chat-download-url"`)

**Out of scope:**
- Changes to `btn--primary` CSS definition in `styles.css` — the existing style (blue background, white text) is the right target appearance.
- Any other buttons or layout changes.

## Current state

Both buttons:
```jsx
className="btn btn--ghost btn--sm"
```

`btn--ghost` is defined in `styles.css` as:
```css
.btn--ghost { background: #fff; box-shadow: var(--shadow); }
```

`btn--primary` already exists and produces a solid blue button with white text:
```css
.btn--primary { background: var(--primary); border-color: var(--primary); color: #fff; }
```

### Follow-up — hover-state regression fix

After the class swap landed, the user reported that hovering either the new `Download NumioConnect-….yaml` button or the adjacent `Open CloudFormation in AWS Console ↗` button produced unreadable text — blue text on a blue background.

**Root cause.** Both buttons render as `<a>` elements (the download anchor uses `download`/`href`; the launch button uses `href` to AWS). A pre-existing global `a:hover { color: var(--primary-hover); }` rule has specificity `(0,1,1)` and beats the non-hover `.btn--primary` `color: #fff` rule (specificity `(0,1,0)`). The original `.btn--primary:hover` rules only re-asserted `background` and `border-color`, never `color`. With `btn--ghost` (white background, blue text) the override was harmless; once the buttons became `btn--primary` (blue background) it produced blue-on-blue.

This was latent in the design system — it would have surfaced for any anchor styled as `btn btn--primary`. The button-prominence change was the trigger, not the underlying defect.

**Fix.** Added `color: #fff` to `.btn--primary:hover` in both stylesheets so the rule's specificity `(0,2,0)` wins over `a:hover`:

- `frontend/src/styles.css` (`.btn--primary:hover` block).
- `frontend/src/numio-design-system.css` (`.btn--primary:hover` block).

Both files define the rule and either can be the cascade winner depending on import order, so both were patched.

**Verification.** Browser hover on both buttons (Download and Open CloudFormation) — white text remains visible on the darker-blue hover background. `npm run build` and `npm test -- --run` (195/195) re-ran clean.
