# Rename AUTH_ENABLED → AUTH_BYPASS, gate to ENVIRONMENT=local

## Problem statement

`AUTH_ENABLED=false` is a confusing double-negative. Spec R16 / R17 / R18 require renaming to `AUTH_BYPASS=true` and gating to `ENVIRONMENT=local`.

## Scope

In scope:
- New env var `AUTH_BYPASS` (default `false`) read by the backend.
- Dual-read: one release supports both names. When `AUTH_ENABLED=false` is set, the backend logs a deprecation warning.
- Startup gate: backend exits non-zero with a clear error if `AUTH_BYPASS=true && ENVIRONMENT != local`.
- Update `.env.example`, `docker-compose.yml`, deployment compose files.

Out of scope:
- Removal of `AUTH_ENABLED` (planned for next release after dual-read).

## Acceptance criteria

- `AUTH_BYPASS=true` activates bypass mode.
- `AUTH_ENABLED=false` (legacy) still activates bypass mode AND emits a deprecation log line.
- `AUTH_BYPASS=true && ENVIRONMENT=production` causes startup to exit 1 with a clear error.
- `.env.example` documents only `AUTH_BYPASS`.

## Quality gates

- Integration test for the env gate covering each combination of `AUTH_BYPASS` and `ENVIRONMENT`.
- Lint and format pass.
