# Frontend — setup, login, set-password flows

## Problem statement

The frontend must implement `/setup`, `/login`, and `/setup/:token`, plus the global redirect logic when `setup/state.needs_first_admin = true`.

## Scope

In scope:
- New routes: `/setup`, `/login`, `/setup/:token`.
- Extend `AuthContext` to call `GET /setup/state` on app mount.
- Redirect interceptor that sends every route to `/setup` while bootstrap is incomplete.
- Form validation (email format, password ≥ 8 characters, no composition rules).
- Error rendering for 401, 403, 404, 410 responses.

Out of scope:
- Settings → Users (covered by `frontend_settings_users`).
- User menu / profile (covered by `frontend_user_menu_profile`).

## Acceptance criteria

- Fresh install: every route redirects to `/setup` until first admin is created.
- After first-admin creation the user lands on the dashboard signed in.
- `/login` accepts credentials and redirects to dashboard on success; shows error inline on failure.
- `/setup/:token` validates the token via `GET /auth/setup/{token}`; renders an explicit empty-state for invalid / expired / used tokens; submits new password via `POST /auth/setup`; signs in on success.
- Bypass mode shows no setup or login page; user lands on dashboard immediately.

## Quality gates

- Vitest unit tests for `AuthContext` and redirect logic.
- `cd frontend && npm test && npm run build` succeed.
- Manual smoke walkthrough on a fresh worktree, documented in PR description.
