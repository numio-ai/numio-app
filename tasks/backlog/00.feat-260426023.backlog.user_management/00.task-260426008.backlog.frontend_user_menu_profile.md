# Frontend — bottom-left user menu and profile page

## Problem statement

The frontend has no real user menu. Today "James C. admin" is hard-coded. The profile page does not exist.

## Scope

In scope:
- Bottom-left user menu component — shows real user name and email; opens with "My profile" and "Sign out".
- `/me` profile page — change name, change password (requires current password), display read-only workspace UUID with copy button.
- Display the workspace UUID read-only on `Settings → Integrations`.
- Sign-out action calls `POST /auth/logout` and redirects to `/login`.

Out of scope:
- Removing the dummy "James" reference (covered by `remove_james_dummy_user`).
- Email or role self-edit (admin-only by spec R10).

## Acceptance criteria

- Menu shows the signed-in user's name and email; clicking opens a popover with My profile / Sign out.
- Sign-out hits `POST /auth/logout` and redirects to `/login`.
- `/me` lets the user change name and password; password change requires correct current password.
- `/me` and `Settings → Integrations` both display the workspace UUID with copy-to-clipboard.
- Bypass mode shows the synthetic-admin name; profile-edit save is disabled (or hidden).

## Quality gates

- Component tests for menu and profile-form validation.
- `cd frontend && npm test && npm run build` succeed.
- Manual smoke test documented in PR.
