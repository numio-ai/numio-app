# In `/agn:implement` skill make documentation sync mandatory, not conditional

## Date
2026-04-18

## Context

The `/agn:implement` skill (`.claude/skills/implement/SKILL.md`) currently frames documentation updates as conditional:

> 6. **Documentation** — If behavior or intent in docs is wrong or incomplete, update the relevant `docs/*` files …

In practice, the user expects every implementation task to keep documentation in sync with the code change in the same unit of work. Treating it as "if wrong or incomplete" invites drift: a change can silently invalidate a runbook, and the drift is only caught later.

Example from 2026-04-18: retargeting container images from GHCR to the GitLab registry immediately invalidated `docs/ops-runbook.md` references to `ghcr.io`. Without explicit guidance, an agent could reasonably defer that patch to a follow-up task, leaving the runbook wrong between merges.

## Problem

The skill does not make "update affected docs as part of the same task" an explicit, mandatory step. Agents can skip it in good faith.

## Goals

1. Make documentation sync an explicit, non-optional step of both `task` and `plan` modes.
2. Require a pre-implementation scan of `docs/` for references touched by the change (registries, endpoints, flags, paths, behavior) so the affected surface is known up front.
3. Require the plan-to-user (before coding starts) to list which docs will be updated.

## Scope

- Edit `.claude/skills/implement/SKILL.md`.
- Rewrite step 6 ("Documentation") as mandatory.
- Add to the "Detailed design first" step a requirement to identify affected docs.
- Add a line to the `plan` mode's per-task contract mirroring the same rule.

## Out of scope

- Other skills (`create-plan`, `qa-integration-test`, etc.) — separate review.
- Automated doc-drift detection in CI.

## Acceptance criteria

1. Step 6 reads as a mandatory action, e.g. "Update every doc affected by this change in the same task — doc drift is a defect introduced by the change."
2. The detailed-design step explicitly requires scanning `docs/` for affected surfaces and listing them in the user-facing plan.
3. The `plan` mode per-task contract includes the same documentation-sync step.
4. Skill file still parses / loads cleanly (frontmatter intact, no broken headings).

## Quality gates

- Re-read by user.
- Next task implemented under `/agn:implement` demonstrably lists the affected docs in its plan before coding.

## Risks

- **Risk:** over-prescribing leads to busy-work for tasks that genuinely touch no docs. Mitigation: rule is "scan and list; update what is affected" — an empty list after an honest scan is acceptable.
