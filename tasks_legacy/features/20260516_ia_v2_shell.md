# Numio IA v2 — shell, routing, and Inbox foundation

## Problem statement

The current Numio shell carries IA debt: a five-group unlabeled sidebar where category names don't match user intent (e.g. "Usage & Cost > Alerts" links to `/feed`, "Optimize" holds resource lists), a top bar with 8 controls and overlapping pills (Data status + Autopilot), and "Overview" as default landing — even though every Overview card duplicates content from another page. Findings, anomalies, and zombies route to four different surfaces. Users have given verbatim feedback that the UI is overloaded and confusing (chat 2026-05-16).

## Objective

The shell renders the IA v2 structure: a 4-group labeled collapsible sidebar (WORK / UNDERSTAND / OPTIMIZE / GOVERN + unlabeled admin), a top bar slimmed to 6 controls with a single "System" status pill, and Inbox (formerly Feed) as the default landing — with the legacy Overview, Zombie Hunter, Configure-Tags, `/financial_planning/*`, and `/optimize/{services,ai-workloads,kubernetes}` URL spaces removed (no redirects per call on 2026-05-16).

## Scope

In scope:
- Replace `OverviewSidebar` with v2 sidebar (4 labeled collapsible groups + admin group; Inbox badge).
- Slim `SlimTopBar` (drop Customize; merge Data + Autopilot pills into a single System pill with popover).
- Routing: default landing `/` → `/inbox`; delete legacy routes and their orphaned page components; sweep in-app references.
- Rename Feed → Inbox; wire the unread badge to a mock hook (backend lands in feature `ia_v2_backend_support`).

Out of scope:
- Building any IA v2 page redesigns (Usage, Resources, Recommendations, Autopilot, Tag Governance, Budgets, Policies) — features B/C/D.
- Mobile shell redesign — the design treats mobile as a separate screen, not in this drop.
- All backend changes — sourced from feature `ia_v2_backend_support`.

## Acceptance criteria

A1. The sidebar renders exactly: `Inbox` (with red unread badge) · group `UNDERSTAND` {Usage, Resources} · group `OPTIMIZE` {Recommendations, Autopilot} · group `GOVERN` {Tag Governance, Budgets, Policies} · {Data Ingestion, Data Explorer, Settings}.

A2. Clicking a group label collapses/expands that group. The group containing the active page is expanded on first render regardless of saved state.

A3. The Inbox badge shows the open-finding count from a frontend mock hook and is hidden when count is 0.

A4. Top bar contains exactly six controls right of the breadcrumb: Ask Numio · Chat · Theme · Bell · Role badge · System pill. No Customize button.

A5. System pill is green when both data-sync and Autopilot are healthy; amber if either is degraded; red on failure. Clicking it opens a popover with both sub-statuses and deep-links to Ingestion and Autopilot.

A6. Visiting `/` redirects to `/inbox`. Visiting `/overview`, `/overview/alerts`, `/overview/activity`, `/zombie-hunter`, `/govern/tags`, `/optimize`, `/optimize/services`, `/optimize/ai-workloads`, `/optimize/kubernetes`, `/financial_planning`, `/financial_planning/budgets`, `/financial_planning/autopilot`, `/controls`, `/alerts`, `/activity` returns the default 404 (no `<Navigate>`).

A7. No in-app link, menu item, or `Navigate` target points at a deprecated URL (verified by zero hits across the `git grep` patterns listed in task `ia_v2_routes`).

A8. `npm run build` and `npm test` pass without modification, except for tests covering deleted pages.

### Notable decisions or deviations

- **Dropped whole-sidebar narrow mode**. The v2 mock is fixed-width 220px with no narrow toggle. `OverviewSidebarContext` was orphaned and removed.
- **`useInboxUnreadCount` and `useAutopilotStatus` are stubs**. Backend tasks `ia_v2_be_inbox_badge` and `ia_v2_be_autopilot_rules` (feature E) replace the bodies without touching consumers.
- **System pill deep-links to `/autopilot`**; sidebar links also point at v2 routes. Several v2 paths (`/autopilot`, `/recommendations`, `/usage`, `/budgets`, `/policies`) 404 in the interim — features B / C / D add them.
- **Aggressive dead-code sweep in task 3**: removed Tab components (OptimizeTabs etc.), Header.jsx, SidebarIcons.jsx, and Controls orphan pages because they had zero consumers after route removal. Each deletion verified by `grep -rln` returning empty.
- **MobileMenu and MobileTabBar pruned, not redesigned** — only entries pointing at deleted routes were removed. A separate mobile-redesign task can rebuild these surfaces.
- **`pages/AIUsage/AIUsagePage.jsx` patched with a placeholder panel** because it embedded `<AIWorkloads />` and `<Recommendations />` as tab content. Feature B's `/usage` replaces this page wholesale.
- **`SettingsSidebar.jsx` + `config/settingsSidebarItems.jsx` left in place** — dead code, but not tied to deleted routes; a future cleanup task can sweep them.

### Interim state going into features B / C / D

The IA-v2 shell is now live: sidebar, top bar, default landing, Inbox. Surviving routes work normally. New v2 destinations that don't yet exist (`/usage`, `/recommendations`, `/autopilot`, `/budgets`, `/policies`) 404 with the inline `<NotFound>` component until their owning features land.
